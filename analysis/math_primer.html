1 · The model in one picture

Agents are closed-loop customers: each of N agents repeatedly cycles

think τthink  →  LLM call (τLLM, cLLM servers)  →  DB query (τDB, cDB servers)  →  repeat

No agent is created or destroyed, the same N agents circulate forever. That feedback makes the load endogenous: if agents queue up at the LLM endpoint, fewer agents reach the DB, so the DB arrival rate drops. Any correct model must solve this loop simultaneously, which is why simple textbook open-queue formulas (M/M/c applied station by station) are wrong here , and why the closed-network machinery of §4 exists.

The repo's DES simulator (SimPy) reconstructs the same loop by explicit event simulation; the analyzer computes the same steady state without simulating, and the page includes an in-browser DES engine (the Monte Carlo tab) so both approaches can be compared.

3 · One endpoint alone, Erlang C and the M/G/c correction

Temporary simplification: fix the rate at which jobs arrive to one station (λ = X) and look at that station in isolation with c identical servers.

Erlang C, the exact M/M/c waiting probability (1917)

offered load: a = λ·τ    per-server load: ρ = a/c

blocking (Erlang B) recursion: B0=1;   Bk = a·Bk−1 / (k + a·Bk−1)
wait probability: π = C(c,a) = Bc / (1 − ρ·(1−Bc))
mean wait: Wq = π / (c/τ − λ)
Reads: "π is the chance all servers are busy when you arrive; once waiting, the server completion stream drains at rate c/τ − λ." The B-recursion avoids the numerically explosive ac/c! form.

Sanity anchors we assert in the suite: C(1, 0.5) = 0.5, C(2, 1) = ⅓, C(5, 3) ≈ 0.2362.

General service (M/G/c): the Allen–Cunneen / Kingman correction

Erlang C is exact only for exponential service (SCV = 1). Kingman's heavy-traffic result says waits grow with (c²a + c²s)/2, the sum of arrival- and service-time variability. The engineering approximation (Allen–Cunneen; Whitt's QNA) multiplies the mean wait by exactly that factor; with Poisson-like closed-loop arrivals (c²a ≈ 1):

Wq,M/G/c ≈ Wq,M/M/c · (1 + c²s)/2    over-inflated waits for spiky service (c²s>1), correctly shrunk for deterministic-like service (c²s→0).

4 · The closed loop, why feedback changes everything (Gordon–Newell, BCMP)

In the loop, each station's arrival rate depends on the other stations' waiting times (X = N / (τthink + RLLM + RDB)). The fix is an old and beautiful one:

Gordon–Newell (1967):   p(n0,…,nK) = (1/G(N)) · ∏stations i fi(ni)

station weight:   fi(n) = ∏m=1..n τi/min(m, ci)
   = τⁿ/n!  for n ≤ c   |   (τc/c!)·(τ/c)n−c  for n > c
think stage (IS):   fthink(n) = τn/n!

The state probability of the whole network factors into per-station weights, this is the product form. It holds exactly for exponential service FCFS multiserver stations and infinite-server nodes (the BCMP theorem details which other types are allowed). G(N) is just the sum of the weights over all ways to place N agents across stations.

Worked micro-example (same numbers our test suite asserts): two M/M/1 stations τ = 1, N = 2 agents, no think. States: agents split (2,0), (1,1), (0,2), all weights equal (τⁿ = 1) so each has probability ⅓. Departures happen only when a station is populated: X = 2/3 loops/s, every station holds L = 2/3·2/2 = 1 agent on average, so R = L/X = 1.5 s and Wq = 0.5 s. Try the open M/M/1 formula instead and you get a very different (wrong) answer , that's the feedback at work.

5 · Buzen's convolution, computing G(N) and the full marginals

Multiplying out the product form naive-Bayes-in-Haskell style would enumerate every split of N agents among stations. Buzen's convolution instead folds the network station by station:

prefix:   Fk(m) = Σj≤m Fk−1(m−j) · fk(j)    (F0 = δ at 0)
after the last station,   G(N) = FK(N)
marginal of station i:   πi(n) = fi(n) · Hi(N−n) / G(N),   Hi = convolution of all stations except i
throughput & occupancy:   X = Σn μi(n)·πi(n) = Σ min(n,ci)/τi · πi(n),   then Ri = Li/X (Little)
  • Computing all marginals needs prefix-and-suffix convolutions, O(K·N²) total, exact, milliseconds for our sizes.
  • We compute in log-space weights to dodge float under/overflow of τⁿ/n!.
  • Every assertion in verify_core.js is a check of this path against independent brute-force CTMC stationary solves (§9), including the K=3 chains your decomposed-DB topology produces (§7).

6 · Latency percentiles, the calibrated wait-mixture model

Buzen gives exact means, not distributions. For percentiles the analyzer builds a closed-form model of each station's wait:

wait ⟶ mixture:   W = 0  with prob (1−π̂);   W ~ Exp(μ̂)  with prob π̂
closed-chain tail rate:   μ̂ = c/τ   a waiting agent in a closed chain sees all c servers busy , the completion stream therefore runs at c/τ, not c/τ−λ as in an open chain (chosen empirically vs MC: §9).
calibration:   π̂ = μ̂·Wexact  (≤1)  ,   pinned so the mixture's mean equals the exact Buzen wait: E[W] = π̂/μ̂ = Wexact

end-to-end latency:   L = think ~ Exp(τthink)  ⊛  (τs1 + Ws1)  ⊛  …  ⊛  (τsK + WsK)  + const

The convolution of these phase distributions runs numerically on a uniform grid (the "grid points" parameter); percentiles are read off the CDF. Because each μ̂ is matched to the exact mean wait, the mean of the percentile engine always equals the exact chain mean (asserted ≤1%). The upper percentiles approximate truth (±10–15% vs Monte Carlo, calibrated rate chosen by bake-off; for exact numbers switch to the MC tab).

7 · Arrival distributions and bottleneck detection

What do agents see when they hit the DB? (arrival theorem)

arrival (Lavenberg–Reiser / Reiser) theorem: in a closed product-form chain, an arriving job at station i sees the network distributed as the equilibrium of the same chain with one agent removed (N−1):

πarri(n) = fi(n) · Hi(N−1)(N−1−n) / G(N−1)(N−1)

Same convolution machinery, evaluated at population N−1, this gives the exact occupancy distribution at DB-arrival instants (the "arrival distribution on the DB" the DES traces report), not merely a mean.

Which endpoint is the bottleneck?

bottleneck = argmaxi ρi    queue-delay share = Wq,i / (τthink + Σ Rk)
  • ρ ranking identifies the gate: capacity added elsewhere buys little until the max-ρ station is relieved (add servers c, cut τ, or cut its traffic by re-sequencing the loop).
  • The delay share splits the loop budget: how much of each cycle is pure waiting at each station.
  • The knee in the sweep chart (§6) marks the agent count where latency growth accelerates, plan capacity below it; the roadmap ticket on "bottleneck attribution" (DES side) tracks the same decomposition from traces.

8 · DES / Monte Carlo, the empirical twin

The MC tab runs the same stochastic model by discrete-event simulation: agents and station servers live on an event list processed in time order; every endpoint is an exact FCFS M/G/c queue (server counts, FIFO queues). Service times draw from a Gamma sampler whose shape is fixed by the SCV dial (1 = exponential, 0 = deterministic; Marsaglia–Tsang 2000), think times exponential.

  • Warm-up: the first fraction of completed cycles is discarded so starting transients don't bias percentiles.
  • Statistical error of percentiles is O(1/√cycles), 20k cycles keep tile jitter small; same seed reproduces the run exactly.
  • Why compare at SCV = 1: the analytic engine is exact there (product form holds for exponential think+service), so the DES should agree with it within sampling error, a strong mutual test. At SCV ≠ 1 the DES is the ground truth and the analytical engines are approximations.

10 · Worked examples with pictures

Every number below comes from the verified engine in core.js, so you can reproduce each one on the analyzer page with the same settings. Each example names the function it shows.

Example 1. Erlang C. Four inference servers, load of three busy servers

Settings: c = 4 servers, mean service τ = 1.5 s, arrival rate λ = 2 calls/s, so the offered load a = λ·τ = 3. The formula gives π = C(4, 3) = 0.509, meaning 51% of arrivals see all four servers busy. Mean wait Wq = π / (c/τ − λ) = 0.51 / 0.667 = 0.76 s.

Example 2. Product form. Three agents, two single-server stations, no think

Every split of the 3 agents between the two stations has the same weight (f(n) = 1 for τ = 1), so all four splits have probability 25%. The engine reports X = 0.75 loops/s and 1.5 agents sitting at each station on average. The same numbers appear in the test suite (verify_core.js cases).

Example 3. Buzen convolution. Folding two station tables

Same setting as Example 2. The convolution sums every compatible pair: G(2) = fA(0)·fB(2) + fA(1)·fB(1) + fA(2)·fB(0) = 1 + 1 + 1 = 3. That constant is all the normalization you need: π(1 agent at A) = 1/3, π(2 at A) = 1/3.

Example 4. Allen-Cunneen correction. Same load, two kinds of jitter

Page defaults (c = 4, τ = 1.5 s) give Wq = 0.175 s at SCV 1. Set the SCV to 0 (constant service, no jitter) and the formula divides the wait by exactly 2, giving 0.087 s. The picture shows the two service distributions behind those numbers.

Example 5. Wait mixture and percentiles. One LLM station at page defaults

The calibrated mixture says 53.4% of calls see no wait at all (a spike right at τ = 1.5 s) and 46.6% wait with an exponential tail of rate μ̂ = 2.67/s. That yields station sojourn percentiles p50 1.50 s, p95 2.34 s, p99 2.94 s, and end-to-end p50 3.36 s, p95 7.97 s.

Example 6. Arrival theorem. What an arriving query finds at the DB

At page defaults the theorem reads the chain with one agent removed, so the arriving query sees on average 0.54 agents already at the DB, and 57.1% of arrivals find the DB empty. The DES histogram in the simulator measures this same quantity.

Example 7. Bottleneck detection. One station at load 0.76, one at 0.08

Page defaults put the LLM station at ρ = 0.755 (bar nearly full) and the DB station at ρ = 0.075 (bar almost empty). The banner on the page names the LLM station, and the table shows the delay share, the part of each cycle the queueing there eats.

Adding DB servers would barely move the numbers, because the LLM station is the one with the full bar. That reasoning is what the bottleneck tile automates.
